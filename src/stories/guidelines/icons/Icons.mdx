## 1 — The `Icon` component

The `Icon` component renders trusted `IconifyIcon` data passed to the `icon` prop
using `@iconify/react/offline`. Icons are bundled locally: there are no API
requests, remote icon names or required global registrations. The library's
internal registry is private. Consumer projects should define and export their
own `IconRegistry`, then pass its entries to the component:

## 2 — Defining the consumer's `IconRegistry`

Each consumer project should have a single `IconRegistry` that exports all the
icons used by that project. Import individual Iconify data modules in this
registry, not throughout application components. Components should import
`IconRegistry` and reference an entry such as `IconRegistry.searchIcon`.

The registry belongs to the consumer project; it is not imported from
`@choco-vanille/ui`. Centralize only the icons the project actually uses, not
an entire Iconify collection. This is a project organization convention:
`Icon` still receives an `IconifyIcon` object, without a provider or a global
Iconify registration.

### Choosing icons

Use the icon that matches the component's meaning. Any Iconify collection or
trusted custom `IconifyIcon` object is supported; do not import an entire
collection when you only need individual icons. Custom SVG bodies are inserted
as markup: never use untrusted user input as icon data. Monochrome artwork uses
`currentColor`; multicolor artwork can retain its fixed colors.

The same data contract applies to `IconButton.icon`, `Button.startIcon`,
`Button.endIcon` and the other component icon props. Refs point to the SVG.
The existing size presets, spin animation, wrapper styling and CSS colors remain
available. Instance IDs keep masks, gradients and clip paths separate and
stable during hydration. If you supply `id`, use a nonempty value that remains
unique after hyphens are replaced with underscores.

**Breaking change:** replace React SVG components and `IconComponent` types with
local `IconifyIcon` data. String icon names are not accepted.

### Naming keys

```
✅  searchIcon, warningIcon, chevronRightIcon, userIcon
❌  SearchIcon, search-icon, SEARCH_ICON, icon_search
```

Use **camelCase** keys with the **`Icon` suffix**, and name them by purpose.
Keep the key stable when replacing the artwork, for example
`warningIcon` even if the underlying collection or shape changes.

Use the same registry for every icon prop, not only `Icon.icon`:
`Button.startIcon`, `Button.endIcon`, `IconButton.icon` and custom feedback
icons should also receive entries from the consumer's `IconRegistry`.

# Plain CSS

The simplest, most portable way to customize the kit. **No build step, no dependencies, no framework** — just redefine the CSS custom properties after importing the kit's stylesheet. Works in every project that can load a stylesheet.

> See **Theme / CSS Variables** for the exhaustive list of token names.

---

## 1. Global rebrand

Override variables on `:root` to change the look of **every** component in the app.

<Source language="css" code={`@import '@my-org/ui-kit/styles.css';

/* Global rebrand */
:root {
  --color-primary:           oklch(0.58 0.18 185); /* teal */
  --color-primaryHover:      oklch(0.52 0.18 185);
  --color-primaryForeground: oklch(1 0 0);
  --color-ring:              oklch(0.58 0.18 185);
  --radius-md:               0.75rem;
}`} />

> **Import order matters.** Your overrides must come **after** the kit's stylesheet, otherwise the kit's own `:root` block wins by source order.

---

## 2. Scoped overrides

Re-skin only a subtree by overriding the variables on a scoped selector. Everything outside the selector keeps the defaults.

<Source language="css" code={`/* Only components inside [data-brand="acme"] are affected */
[data-brand="acme"] {
  --color-primary:      oklch(0.55 0.22 130); /* green */
  --color-primaryHover: oklch(0.49 0.22 130);
}`} />

<Source language="tsx" code={`<div data-brand="acme">
  {/* every kit component here uses the green primary */}
  <Button variant="contained" color="primary" label="Acme action" />
</div>`} />

Because CSS variables cascade, you can nest scopes and even override a single token deep in the tree.

---

## 3. Common tokens to override

| Token | Controls |
|---|---|
| `--color-primary` / `--color-primaryHover` | Primary action colour and its hover state |
| `--color-primaryForeground` | Text/icon colour on top of `primary` |
| `--color-ring` | Focus ring colour |
| `--color-card` / `--color-cardForeground` | Surface background and its text |
| `--radius-md` | Default corner radius |

---

## Dark mode

`:root` is **light** by default; dark mode follows the OS automatically. Force a mode per subtree with the `data-theme` attribute, and scope overrides to dark by targeting `[data-theme="dark"]`.

<Source language="css" code={`/* A brand override that only applies in dark mode */
[data-theme="dark"] {
  --color-primary: oklch(0.70 0.16 185);
}`} />

<Source language="tsx" code={`<div data-theme="dark">…</div>   {/* force dark   */}
<div data-theme="light">…</div>  {/* force light  */}
{/* no attribute → follow the OS (prefers-color-scheme) */}`} />

| Selector | Result |
|---|---|
| `:root` (no `data-theme`) | Light, unless the OS prefers dark |
| `[data-theme="dark"]` | Always dark |
| `[data-theme="light"]` | Always light (opts out of the OS rule) |

---

## When to use this

- ✅ Any project — React, Vue, server-rendered, plain HTML.
- ✅ You want the least amount of tooling possible.
- ✅ Quick theming or a one-off rebrand.

For **typed** overrides with autocomplete, see the **Vanilla Extract** page. For **Tailwind utilities** mapped to these tokens, see the **Tailwind** page.

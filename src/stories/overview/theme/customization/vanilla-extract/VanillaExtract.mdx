# Vanilla Extract

This is how the kit itself is built, and the only approach that gives you **fully typed, autocompleted** access to every token. If you author styles with Vanilla Extract, you get compile-time safety: typos in token names become TypeScript errors.

> Requires `@vanilla-extract/css` in your project (it's the kit's styling engine).

---

## 0. Application setup

Import a kit component from `@choco-vanille/ui` in the application entry.
The typed `vars` contract references the CSS variables loaded by that package
import; it does not emit a second stylesheet.

---

## 1. Consume tokens via the typed `vars` object

Import `vars` from the kit and reference tokens directly — full autocomplete, no magic strings.

<Source language="ts" code={`// MyCard.css.ts
import { style } from '@vanilla-extract/css';
import { vars } from '@choco-vanille/ui';

export const card = style({
  background:   vars.color.surface,
  color:        vars.color.surfaceForeground,
  padding:      vars.space.lg,
  borderRadius: vars.radius.md,
  boxShadow:    vars.shadow.sm,
});`} />

`vars` is the typed contract — `vars.color.surface` compiles to `var(--color-surface)`, so your styles stay in sync with the kit and react to dark mode / scoped overrides automatically.

---

## 2. Type-safe token overrides

Use Vanilla Extract's own `globalStyle` with the typed `vars` contract. The
library deliberately exposes CSS variables rather than a Vanilla Extract-only
override helper, so the same customization remains possible with any CSS tool.

<Source language="ts" code={`// brand.css.ts
import { globalStyle } from '@vanilla-extract/css';
import { vars } from '@choco-vanille/ui';

globalStyle('[data-brand="acme"]', {
  vars: {
    [vars.color.primary]:           'oklch(0.58 0.18 185)',
    [vars.color.primaryHover]:      'oklch(0.52 0.18 185)',
    [vars.color.primaryForeground]: 'oklch(1 0 0)',
    [vars.color.focusRing]:              'oklch(0.58 0.18 185)',
  },
});
`} />

Then wrap the section in React with the matching attribute:

<Source language="tsx" code={`<div data-brand="acme">
  {/* all kit components here use the overridden colours */}
  <Button variant="contained" color="primary" label="Acme action" />
</div>`} />

## Cascade layers

The kit emits its token variables inside `@layer ${THEME_LAYER}` and its reset styles inside `@layer ${RESET_LAYER}`. That means your own unlayered Vanilla Extract styles automatically win over the kit's defaults. If you want to override the kit inside a layer of your own, declare your layer *after* the kit's layers:

<Source language="css" code={`/* Your app's CSS */
@layer ${THEME_LAYER}, ${RESET_LAYER}, app;

@layer app {
  :root {
    --color-primary: oklch(0.55 0.2 180);
  }
}`} />

## Dark mode

Dark mode is just another scope. Because `vars.color.*` compiles to `var(--color-*)`, any style that consumes `vars` reacts to `[data-theme="dark"]` or `.${THEME_DARK_CLASS}` automatically — no conditional logic needed.

> **React app?** If you need programmatic theme switching, the kit's `<ThemeProvider>` manages `data-theme` via React state — your Vanilla Extract styles read the same `var(--color-*)` variables so they respond automatically. See the **ThemeProvider** page.

To give a token a **dark-specific** value, target the dark scope with
`globalStyle`:

<Source language="ts" code={`// brand.css.ts
import { globalStyle } from '@vanilla-extract/css';
import { vars } from '@choco-vanille/ui';

globalStyle('[data-theme="dark"]', {
  vars: {
    [vars.color.primary]: 'oklch(0.70 0.16 185)',
  },
});
`} />

<Source language="tsx" code={`<div data-theme="dark">…</div>                  {/* force dark for this subtree     */}
<div className="${THEME_DARK_CLASS}">…</div>   {/* same, using a class             */}
<div className="${THEME_LIGHT_CLASS}">…</div>  {/* force light inside a dark scope */}
<html data-theme="light">…</html>              {/* opt the app out of OS dark (root) */}
{/* no attribute → follow the OS (prefers-color-scheme) */}`} />

> The kit defines light tokens on `:root` and also exposes `.${THEME_LIGHT_CLASS}` / \`[data-theme="light"]\` to re-assert light tokens inside a dark subtree.

---

## When to use this

- ✅ You author styles with Vanilla Extract and want typed tokens.
- ✅ You want the compiler to catch token typos.
- ✅ You're building reusable themed components on top of the kit.
- ✅ React app: if you also need a theme toggle, `ThemeProvider` adds React state management on top — your Vanilla Extract styles are unchanged.

If you don't use Vanilla Extract, the **Plain CSS** page achieves the same overrides with raw CSS variables and zero tooling. For **React-driven** theme management, see the **ThemeProvider** page.

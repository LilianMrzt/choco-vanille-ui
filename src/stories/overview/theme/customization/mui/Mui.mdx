# MUI (Material UI)

**First, the honest answer: this kit is _not_ built on MUI.** Its components are built on [Base UI](https://base-ui.com/) primitives and styled with [Vanilla Extract](https://vanilla-extract.style/), reading plain CSS variables. MUI's `ThemeProvider` and `createTheme` have **no effect** on the kit's components — wrapping them in a MUI theme will not re-skin a kit `<Button>`.

So MUI can't _drive_ this kit's theme. But there's a genuinely useful pattern: if your app renders **both** MUI components and kit components, you can make MUI **consume the kit's tokens** so the two libraries look consistent. That bridge is what this page is about.

> **Direction of truth:** the kit's CSS variables → MUI's theme. To change the kit itself, override the CSS variables (see **Plain CSS** / **Vanilla Extract**). Those same variables then feed MUI below.

---

## 0. Load the kit stylesheet

Import the kit stylesheet once before rendering either library. MUI's
`ThemeProvider` does not load the kit's CSS variables.

<Source language="ts" code={`// main.tsx
import '@my-org/ui-kit/styles.css';`} />

---

## 1. Feed the kit's tokens into a MUI theme

`createTheme` accepts any CSS value, including `var(...)`. Point MUI's palette at the kit's variables so both libraries draw from one source.

<Source language="ts" code={`// theme.ts
import { createTheme } from '@mui/material/styles';

export const muiTheme = createTheme({
  palette: {
    primary: {
      main:         'var(--color-primary)',
      dark:         'var(--color-primaryHover)',
      contrastText: 'var(--color-primaryForeground)',
    },
    background: {
      paper:   'var(--color-card)',
      default: 'var(--color-background)',
    },
    text: {
      primary: 'var(--color-foreground)',
    },
  },
  shape: {
    // MUI expects a number; if you keep radius in rem, prefer the CSS-variables
    // approach in section 3 instead of hard-coding here.
    borderRadius: 8,
  },
});`} />

<Source language="tsx" code={`// App.tsx
import { ThemeProvider } from '@mui/material/styles';
import { muiTheme } from './theme';

<ThemeProvider theme={muiTheme}>
  {/* MUI components now use the kit's primary colour… */}
  <Button variant="contained">MUI button</Button>
  {/* …and sit next to kit components that share the same tokens */}
</ThemeProvider>`} />

Because the values are `var(...)`, MUI components automatically follow the kit's **dark mode** and **scoped overrides** at runtime — no second theme to maintain.

---

## 2. Keep it consistent — don't fork the palette

The win here is a **single source of truth**. Avoid copying hard-coded hex/oklch values into `createTheme`: that duplicates the palette and the two libraries will drift apart (and MUI won't react to `[data-theme="dark"]`). Always reference the variable.

| Do | Don't |
|---|---|
| `main: 'var(--color-primary)'` | `main: '#0ea5a4'` |
| Let `[data-theme="dark"]` flip the variable | Maintain a separate MUI dark palette by hand |

---

## 3. (Optional) MUI CSS theme variables mode

MUI v6+ can emit its own theme as CSS variables. Enable `cssVariables` and you can still alias the kit's tokens, keeping everything resolvable at runtime:

<Source language="ts" code={`import { createTheme } from '@mui/material/styles';

export const muiTheme = createTheme({
  cssVariables: true, // MUI exposes --mui-* variables
  palette: {
    primary: { main: 'var(--color-primary)' },
  },
});`} />

This is handy if other parts of your app already consume `--mui-*` variables and you want them transparently backed by the kit's palette.

---

## Dark mode

You do **not** need MUI's `palette.mode: 'dark'` machinery for the kit's tokens. Since the MUI palette references `var(--color-*)`, simply toggling the kit's `data-theme` or `.${THEME_DARK_CLASS}` class re-colours MUI too:

> **React app?** If you need programmatic theme switching, wrap both providers with the kit's `<ThemeProvider>` — it manages `data-theme` via React state and MUI's palette continues reading the same `var(--color-*)` variables unchanged.

<Source language="tsx" code={`import { ThemeProvider as KitThemeProvider } from '@my-org/ui-kit';
import { ThemeProvider as MuiThemeProvider } from '@mui/material/styles';
import { muiTheme } from './theme';

<KitThemeProvider scope="document" defaultTheme="system">
  {/* MUI palette reads var(--color-*) — it follows the kit's data-theme */}
  <MuiThemeProvider theme={muiTheme}>
    <App />
  </MuiThemeProvider>
</KitThemeProvider>`} />

<Source language="tsx" code={`<div data-theme="dark">
  <ThemeProvider theme={muiTheme}>
    <Button variant="contained">Follows the kit's dark mode</Button>
  </ThemeProvider>
</div>

<div className="${THEME_DARK_CLASS}">
  <ThemeProvider theme={muiTheme}>
    <Button variant="contained">Also follows the kit's dark mode</Button>
  </ThemeProvider>
</div>`} />

If you also rely on MUI's own light/dark components (e.g. its `mode`-aware defaults), keep MUI's `mode` in sync with the attribute you set on `data-theme` — but the **colours** still come from the kit's variables.

---

## When to use this

- ✅ Your app mixes MUI components **and** kit components and you want one consistent palette.
- ✅ You want MUI to inherit the kit's dark mode and scoped overrides for free.
- ✅ Combine with the kit's **ThemeProvider** for React-driven theme switching — MUI follows the kit's `data-theme` automatically since its palette reads `var(--color-*)`; no changes to your MUI theme object.- ❌ You expected MUI's theme to restyle the kit's components — it can't; the kit doesn't read MUI's theme. Use **Plain CSS** or **Vanilla Extract** to change the kit itself.

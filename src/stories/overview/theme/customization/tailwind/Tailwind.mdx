# Tailwind

If your app already uses Tailwind, expose the kit's CSS variables as **Tailwind tokens** so you can use them through utilities like `bg-brand` or `rounded-card`. The kit's components keep reading their own variables — you are only adding Tailwind aliases on top.

> Use **distinct names** (e.g. `brand`, not `primary`) so your Tailwind tokens don't clash with the kit's own variable names.

---

## Tailwind v4 (CSS-first `@theme`)

In v4 the theme lives in CSS. Map the kit's variables into the `@theme` block.

<Source language="css" code={`/* app.css */
@import 'tailwindcss';
@import '@my-org/ui-kit/styles.css';

@theme {
  --color-brand:    var(--color-primary);
  --color-brand-fg: var(--color-primaryForeground);
  --color-surface:  var(--color-card);
  --radius-card:    var(--radius-md);
}`} />

<Source language="tsx" code={`// Now use the generated utilities anywhere:
<button className="bg-brand text-brand-fg rounded-card px-4 py-2">
  Branded button
</button>`} />

---

## Tailwind v3 (`tailwind.config.js`)

In v3, extend the theme in the config file and point each token at the kit's CSS variable.

<Source language="js" code={`// tailwind.config.js
export default {
  theme: {
    extend: {
      colors: {
        brand:      'var(--color-primary)',
        'brand-fg': 'var(--color-primaryForeground)',
        surface:    'var(--color-card)',
      },
      borderRadius: { card: 'var(--radius-md)' },
    },
  },
}`} />

---

## Why reference the variables (not copy the values)?

Because the utilities resolve at **runtime** through `var(...)`, they automatically pick up:

- **Dark mode** — when `[data-theme="dark"]` flips the variable, `bg-brand` follows.
- **Scoped overrides** — a `[data-brand="acme"]` block (see **Plain CSS**) re-colours `bg-brand` inside that subtree with zero extra config.

If you copied hard-coded colours into the Tailwind config instead, you'd lose all of that.

---

## Dark mode

Because the utilities resolve through `var(...)` at runtime, dark mode needs **no extra Tailwind config** — flip `[data-theme="dark"]` and `bg-brand` follows the variable. To give the Tailwind aliases dark-specific values, override the underlying kit variable in the dark scope:

<Source language="css" code={`/* app.css — only affects dark mode */
[data-theme="dark"] {
  --color-primary: oklch(0.70 0.16 185); /* bg-brand picks this up automatically */
}`} />

<Source language="tsx" code={`<div data-theme="dark">
  <button className="bg-brand text-brand-fg rounded-card px-4 py-2">
    Dark-aware branded button
  </button>
</div>`} />

> Avoid Tailwind's own `dark:` variant for kit tokens — it would double-manage theming. Let the kit's `data-theme` scope drive the variables and Tailwind utilities inherit for free.

---

## When to use this

- ✅ Your app is already Tailwind-based.
- ✅ You want to mix raw Tailwind markup with kit components and share one palette.

For projects without Tailwind, the **Plain CSS** page achieves the same result with no tooling.

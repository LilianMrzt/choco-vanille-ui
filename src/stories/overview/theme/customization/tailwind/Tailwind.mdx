# Tailwind

Already using Tailwind? You can do two things with the kit's tokens:

- **Override** the kit's colors globally (e.g. make `primary` red) — affects every kit component.
- **Expose** the kit's variables as Tailwind utilities (`bg-primary`, `rounded-md`, …).

Both work because every kit component reads its colours through `var(--color-*)` at runtime.

---

## 1. Setup

Install Tailwind v4 and add its Vite plugin.

<Source language="bash" code={`npm install tailwindcss @tailwindcss/vite`} />

<Source language="ts" code={`// vite.config.ts
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import tailwindcss from '@tailwindcss/vite'

export default defineConfig({
  plugins: [tailwindcss(), react()],
})`} />

Import Tailwind in your main CSS file. Importing a kit component from
`@choco-vanille/ui` loads its CSS; keep your overrides in the application CSS.

<Source language="css" code={`/* index.css */
@import 'tailwindcss';

/* ↓ your overrides / @theme go below this line */`} />

> The kit's token layer has lower cascade priority than your unlayered application
> rules, so no manual stylesheet ordering is required.

---

## 2. Override the kit's colours

Redefine the kit's CSS variables under `:root` (and `[data-theme="dark"]` / `.${THEME_DARK_CLASS}` for dark mode). Place them
in your application stylesheet.

<Source language="css" code={`/* index.css */

/* Light */
:root {
  --color-primary:                 oklch(54.5% .26 25);
  --color-primaryHover:            oklch(48.8% .24 25);
  --color-primaryActive:           oklch(42.4% .21 25);
  --color-primaryForeground:       oklch(100% 0 0);
  --color-primarySubtle:           oklch(97.1% .015 25);
  --color-primarySubtleHover:      oklch(93.6% .04 25);
  --color-primarySubtleActive:     oklch(88.5% .08 25);
  --color-primarySubtleForeground: oklch(48.8% .24 25);
  --color-primarySubtleBorder:     oklch(88.5% .08 25);
  --color-ring:                    oklch(54.5% .26 25);
}

/* Dark — matches the kit's dark selectors */
[data-theme="dark"],
.${THEME_DARK_CLASS} {
  --color-primary:                 oklch(62.3% .23 25);
  --color-primaryHover:            oklch(70.7% .19 25);
  --color-primaryActive:           oklch(80.8% .13 25);
  --color-primaryForeground:       oklch(14.3% .008 264);
  --color-primarySubtle:           oklch(28.2% .1 25);
  --color-primarySubtleHover:      oklch(37.9% .15 25);
  --color-primarySubtleActive:     oklch(42.4% .2 25);
  --color-primarySubtleForeground: oklch(88.5% .062 25);
  --color-primarySubtleBorder:     oklch(42.4% .2 25);
  --color-ring:                    oklch(62.3% .23 25);
}`} />

> The kit's tokens live in `@layer ${THEME_LAYER}`, so these unlayered overrides win without needing `!important`.

That's it — every kit component (`<Button>`, `<Checkbox>`, …) now uses your colours. No component
changes, no config.

## 3. Use kit tokens as Tailwind utilities

Optional. If you also want Tailwind classes backed by the kit's tokens, add a `@theme` block.

### `@theme inline` — keep the kit's names (`bg-primary`)

Generates utilities that inline `var(...)` directly, **without** creating new variables. Best when you
want Tailwind classes that share the kit's token names — they also follow your overrides above.

<Source language="css" code={`/* index.css */
@theme inline {
  --color-primary:           var(--color-primary);
  --color-primaryForeground: var(--color-primaryForeground);
  --color-secondary:         var(--color-secondary);
  --color-background:        var(--color-background);
  --color-foreground:        var(--color-foreground);
  --color-muted:             var(--color-muted);
  --color-border:            var(--color-border);
  --color-ring:              var(--color-ring);

  --radius-sm:   var(--radius-sm);
  --radius-md:   var(--radius-md);
  --radius-lg:   var(--radius-lg);
  --radius-full: var(--radius-full);
}`} />

<Source language="tsx" code={`<button className="bg-primary text-primaryForeground rounded-md px-4 py-2">
  Uses kit tokens
</button>`} />

### `@theme` — use your own names (`bg-brand`)

Use this when your app has a different naming convention. Tailwind creates a new variable and utility.

<Source language="css" code={`/* index.css */
@theme {
  --color-brand:    var(--color-primary);
  --color-brand-fg: var(--color-primaryForeground);
  --color-surface:  var(--color-card);
  --radius-card:    var(--radius-md);
}`} />

<Source language="tsx" code={`<button className="bg-brand text-brand-fg rounded-card px-4 py-2">
  Branded button
</button>`} />

> | | `@theme` | `@theme inline` |
> |---|---|---|
> | Creates a new CSS variable | ✅ yes | ❌ no |
> | Token name in utility | new name (`bg-brand`) | same as kit (`bg-primary`) |
> | Use when | you need distinct names | you want to reuse kit names |

## Tailwind v3

Point config tokens at the kit's variables.

<Source language="js" code={`// tailwind.config.js
export default {
  theme: {
    extend: {
      colors: {
        brand:      'var(--color-primary)',
        'brand-fg': 'var(--color-primaryForeground)',
        surface:    'var(--color-card)',
      },
      borderRadius: { card: 'var(--radius-md)' },
    },
  },
}`} />

---

## Why `var(...)` and not hard-coded values?

Because utilities resolve at **runtime**, they automatically follow:

- **Dark mode** — `[data-theme="dark"]` or `.${THEME_DARK_CLASS}` flips the variable, your utilities follow. No `dark:` variant needed.
- **Overrides** — your `:root` block re-colours kit components *and* Tailwind utilities at once.
- **Scoped theming** — a `[data-brand="acme"]` wrapper re-themes its subtree for free.

> **React app?** The kit's `<ThemeProvider>` toggles `data-theme` via React state; your utilities
> resolve through the same `var(--color-*)` chain, so they follow automatically. See **ThemeProvider**.

> **Cascade layers.** Because the kit's variables are in `@layer ${THEME_LAYER}`, your Tailwind `@theme` / `@theme inline` utilities (which are unlayered by default) take precedence automatically.

For projects without Tailwind, see **Plain CSS** — same result, no tooling.

# ThemeProvider

> **`ThemeProvider` is not a new customization method.** It is a React convenience wrapper that manages the `data-theme` attribute on a DOM element for you. The kit's components still read the exact same CSS custom properties they always did — nothing about that contract changes.

Use it when your project is React-based and you want **programmatic theme switching** (dark mode toggle, OS preference tracking, `useTheme` hook) without writing DOM manipulation code yourself. Import components from `@choco-vanille/ui` as usual; its default document scope also keeps body-mounted portals in the active theme. Your existing CSS customization approach — Plain CSS, CSS Modules, Tailwind, Vanilla Extract, or any other — stays exactly as-is alongside it.

> If you need to theme a subtree without touching the host document's `data-theme` attribute, use the `.${THEME_DARK_CLASS}` or `.${THEME_LIGHT_CLASS}` class directly on any ancestor. `ThemeProvider` uses `data-theme` for React state management, but the underlying CSS responds to both forms.

---

## What it does (and what it doesn't)

| What `ThemeProvider` does | What it does **not** do |
|---|---|
| Sets `data-theme="<theme-name>"` on a wrapper `<div>` or `<html>` when `scope="document"` | Change how kit components read tokens |
| Tracks `prefers-color-scheme` and updates on OS change | Replace Plain CSS / Tailwind / Vanilla Extract overrides |
| Exposes `{ theme, resolvedTheme, setTheme }` via React context | Introduce a new styling engine or token format |
| Injects `tokens` prop values as inline CSS custom properties | Prevent any other `data-theme` management strategy from working |

## Quick start

<Source language="tsx" code={`import { ThemeProvider } from '@choco-vanille/ui'

// Wrap your whole app — follows the OS preference by default.
export default function App() {
  return (
    <ThemeProvider defaultTheme="system">
      <YourApp />
    </ThemeProvider>
  )
}`} />

That's it. Every kit component inside the tree now automatically switches between light and dark following the OS setting, and you can change it programmatically at any time via the `useTheme` hook.

For server-rendered applications, `system` resolves to light on the server and
during hydration, then synchronizes with the browser preference. This avoids
hydration mismatches, but can briefly show the light theme on a dark system.

---

## Custom theme names

`light`, `dark` and `system` are the built-in values, but the provider also
accepts consumer-defined names. Add the matching CSS rules in your application
stylesheet, then pass the name to the provider:

<Source language="tsx" code={`<ThemeProvider theme="light-green">
  <YourApp />
</ThemeProvider>

// Your stylesheet:
// [data-theme="light-green"] {
//   --color-primary-main: oklch(0.55 0.2 145);
// }`} />

The provider treats `light-green` as an opaque theme name and exposes it
through both `theme` and `resolvedTheme`. The consumer remains responsible for
defining its CSS variables.

## Props

| Prop | Type | Default | Description |
|---|---|---|---|
| `defaultTheme` | `string` | `'system'` | Initial theme name (uncontrolled). |
| `theme` | `string` | — | Controlled theme name. Built-in values are `light`, `dark` and `system`. |
| `onThemeChange` | `(theme: string) => void` | — | Fired whenever a child calls `setTheme`. |
| `scope` | `'subtree' \| 'document'` | `'document'` | Apply the theme to the wrapper or to `<html>`. Use `subtree` for an independent themed zone. |
| `themeTransitionDuration` | `number` | `0` | Optional duration in milliseconds for color-related theme transitions. `0` disables transitions. |
| `tokens` | `ThemeColorOverrides` | — | Readonly partial semantic color overrides. Applied to the wrapper or `<html>` according to `scope`. |
| `...divProps` | `React.HTMLAttributes<HTMLDivElement>` | — | All standard `<div>` props (`className`, `style`, `id`, …). |

## useTheme hook

`useTheme` reads the nearest `ThemeProvider` context.

<Source language="tsx" code={`import { useTheme } from '@choco-vanille/ui'

function DarkModeToggle() {
  const { resolvedTheme, setTheme } = useTheme()

  return (
    <button onClick={() => setTheme(resolvedTheme === 'dark' ? 'light' : 'dark')}>
      Switch to {resolvedTheme === 'dark' ? 'light' : 'dark'} mode
    </button>
  )
}`} />

| Value | Type | Description |
|---|---|---|
| `theme` | `string` | Active theme name, including `'system'` if that's what was set. |
| `resolvedTheme` | `string` | Concrete theme name — never `'system'`. Safe for conditional rendering. |
| `setTheme` | `(theme: string) => void` | Change the active theme. |

> `useTheme` is safe to call **outside** a `ThemeProvider` — it returns `{ theme: 'system', resolvedTheme: 'light', setTheme: noop }` as a fallback.

## Uncontrolled vs controlled

### Uncontrolled (default)

The provider owns the state. Use `defaultTheme` to seed it and `useTheme().setTheme` to change it from anywhere in the tree.

<Source language="tsx" code={`<ThemeProvider defaultTheme="dark">
  {/* starts dark; DarkModeToggle can switch it at runtime */}
  <DarkModeToggle />
  <App />
</ThemeProvider>`} />

### Controlled

The parent owns the state. Pass `theme` and handle `onThemeChange` to stay in sync.

<Source language="tsx" code={`const [mode, setMode] = useState<ThemeMode>('system')

<ThemeProvider theme={mode} onThemeChange={setMode}>
  <App />
</ThemeProvider>`} />

## Runtime token overrides

The `tokens` prop accepts `ThemeColorOverrides`, a readonly partial object of
isolated tokens and direct group leaves, and injects them as `--color-*` inline styles.
Only supplied leaves are overridden; sibling values remain inherited.
With `scope="document"`, the overrides are applied to `<html>`; with
`scope="subtree"`, they are applied to the wrapper. It intentionally covers
semantic colors only, not editor palettes or other categories.

Overrides accept hex, RGB, OKLCH, and other valid CSS colors. They do not derive
hover, pressed, or foreground values from the primary fill. Override the matching
states together and check contrast in every state of both themes.

<Source language="tsx" code={`import { Button, ThemeProvider, type ThemeColorOverrides } from '@choco-vanille/ui'

const tealColors = {
  primary: {
    main: '#0f766e',
    hover: '#115e59',
    pressed: '#134e4a',
    foreground: '#ffffff',
    subtle: '#f0fdfa',
    subtleHover: '#ccfbf1',
    subtlePressed: '#99f6e4',
    subtleForeground: '#134e4a',
    border: '#0f766e',
    subtleBorder: '#0f766e',
  },
  focusRing: '#0f766e',
} satisfies ThemeColorOverrides

export const Example = () => (
  <ThemeProvider
    theme="light"
    tokens={tealColors}
  >
    {/* Every kit component here uses the teal primary */}
    <Button variant="contained" color="primary" label="Acme action" />
  </ThemeProvider>
)`} />

> **Tip.** `tokens` overrides apply on top of whichever theme is active. You can combine them with `theme="dark"` to create a fully custom dark-mode variant.
>
> **Cascade layers.** Inline styles are not affected by `@layer` ordering, so `tokens` always wins over stylesheet overrides unless another inline style is present.

## Scoped theming

With `scope="subtree"`, the provider renders a `<div>` and you can
nest several providers to create independent theme zones inside the same page.
Portals from a scoped zone still need a portal container inside that zone if
they must use its theme.

<Source language="tsx" code={`<ThemeProvider defaultTheme="light">
  {/* default light zone */}
  <Header />

  <ThemeProvider scope="subtree" theme="dark" tokens={{ primary: { main: 'oklch(0.70 0.16 185)' } }}>
    {/* dark zone with a custom primary */}
    <Sidebar />
  </ThemeProvider>

  <Main />
</ThemeProvider>`} />

---

## Global (app-level) theming

Render `ThemeProvider scope="document"` at the very top of your React tree to
apply the theme to `<html>`. This is the recommended mode for applications
using body-mounted portals.

<Source language="tsx" code={`// main.tsx
import { ThemeProvider } from '@choco-vanille/ui'
import { createRoot } from 'react-dom/client'
import App from './App'

createRoot(document.getElementById('root')!).render(
  <ThemeProvider defaultTheme="system" style={{ minHeight: '100dvh' }}>
    <App />
  </ThemeProvider>
)`} />

## Comparison with other approaches

| | ThemeProvider | Plain CSS | Vanilla Extract |
|---|---|---|---|
| Build step needed | ❌ | ❌ | ✅ |
| Runtime switching | ✅ | Manual DOM manipulation | ❌ (build-time) |
| `useTheme` hook | ✅ | ❌ | ❌ |
| Fully typed tokens | Via `ThemeColor` | ❌ | ✅ |
| Works in any framework | React only | ✅ | ✅ |

Use `ThemeProvider` when you need **React-driven** theme switching or want to inject token overrides at runtime. For static builds or non-React projects, the Plain CSS or Vanilla Extract pages are the right tool.

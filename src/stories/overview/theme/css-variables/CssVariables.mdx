# CSS Variables

The complete list of every CSS custom property exposed by `@choco-vanille/ui`.
All values are read directly from the theme source — this page updates automatically when tokens change.

**Naming rule:** join every token-path segment with `-`, preserving its case:
`vars.color.primary.hover` → `--color-primary-hover`;
`vars.color.primary.subtleForeground` → `--color-primary-subtleForeground`.

Semantic colors, editor palettes, and shadow tokens are **theme-dependent**. All other tokens are identical across themes. Built-in color ramps use sRGB hex values; overrides still accept any valid CSS color, including OKLCH.

The semantic vocabulary uses `danger`, `neutral`, `accent*`, and `focusRing`.
`currentColor` and `transparent` are also token keys and map to
`--color-currentColor` and `--color-transparent`.

## Migrating color names

This replaces the previous names rather than adding aliases. Update theme
objects, provider overrides, foundation/layout color props, and CSS variable
overrides together.

| Previous token | Semantic token |
| --- | --- |
| `foreground`, `foregroundMuted`, `foregroundSubtle` | `text.primary`, `text.secondary`, `text.tertiary` |
| `surface`, `surfaceForeground` | `surface.main`, `surface.foreground` |
| `surfaceElevated`, `surfaceElevatedForeground` | `surface.elevated`, `surface.elevatedForeground` |
| `surfaceMuted`, `surfaceMutedForeground` | `surface.muted`, `surface.mutedForeground` |
| `{family}`, `{family}Hover`, `{family}Active` | `{family}.main`, `{family}.hover`, `{family}.pressed` |
| `{family}Foreground`, `{family}SubtleForeground` | `{family}.foreground`, `{family}.subtleForeground` |
| `{family}Subtle`, `{family}SubtleHover`, `{family}SubtleActive` | `{family}.subtle`, `{family}.subtleHover`, `{family}.subtlePressed` |
| `{family}SubtleBorder` | `{family}.subtleBorder` (plus new independent `{family}.border`) |
| `border`, `borderStrong` | `border.main`, `border.strong` (plus `subtle`, `muted`, `stronger`) |
| `ring` | `focusRing` |
| `link`, `linkHover`, `linkActive` | `link.main`, `link.hover`, `link.pressed` |
| `highlight`, `highlightForeground` | `highlight.main`, `highlight.foreground` |
| `skeletonBase`, `skeletonHighlight` | `skeleton.base`, `skeleton.highlight` |

The same mapping applies to `--color-*` variable names. Independent component
intent props are unchanged: for example, Button's `color="destructive"` maps to
`danger` tokens. Box, Typography and Icon accept CSS values directly:
`color={vars.color.danger.main}` or `color="var(--app-color)"`, not token names.
The raw palette and editor palette names are unchanged.

## Editor colors

Editor and rich-text renderer palettes keep their named tones, for example
`vars.editorColors.ocean.base` → `--editorColors-ocean-base`. These are editorial
color choices, not semantic action foregrounds; assess their contrast on the
actual text or highlight surface.

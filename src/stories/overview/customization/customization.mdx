# Customization

Customize the library by overriding its CSS custom properties, globally or for
a subtree. No component changes or additional styling library are required;
Vanilla Extract is recommended if you want typed token access.

See [Docs / CSS Variables](?path=/story/docs-css-variables--reference) for variable
names and [Docs / Tokens](?path=/story/docs-tokens--all-tokens) for token values.

## Numeric scales

Spacing, font-size and radius tokens use **numeric** keys. They reference
pixels at a 16px root; values remain in rem except spacing `0` and fixed `1px`.
Use `vars.space[16]`, `vars.fontSize[14]`, `vars.radius[8]` and component
props such as `padding={16}` or `fontSize={14}`. Props accept only numbers
from their finite token scale. There are no legacy named aliases, quoted numeric
props or implicit multipliers. `radius.full` remains available.

Typography owns line-height and letter-spacing styling; these are no longer
theme groups. Its `letterSpacing` prop accepts a CSS value, such as `0.025em`.
Font families and weights, motion and stacking scales are unchanged.
Both shadow families expose `none`, `xs`, `sm`, `md`, `lg`, `xl`.
Independent component size axes, such as Button's `size="md"`, are unchanged.

## Override tokens with CSS

Import components from `@choco-vanille/ui` as usual: compatible bundlers load
their static CSS imports. If your pipeline requires explicit CSS loading,
import `@choco-vanille/ui/styles.css` once in the application entry.

Add your overrides to an application stylesheet:

The theme's default tokens live in a CSS cascade layer:

<Source language="css" code={renderSource(customizationExample2, { THEME_LAYER: THEME_LAYER })} />

Keep application overrides **outside a layer** to take precedence over normal
layered defaults on the same element, without `!important`. If your application
uses layers, explicitly order its override layer after the library's theme
layer before either layer is first declared.

| Token | Purpose |
| --- | --- |
| `--color-primary-main`, `--color-primary-hover`, `--color-primary-pressed` | Filled primary action states |
| `--color-primary-foreground` | Text and icons on filled primary actions |
| `--color-surface-main`, `--color-surface-foreground` | Surface background and foreground |
| `--color-focusRing` | Focus indicator |
| `--space-12`, `--radius-8` | Spacing and corner radius |

When rebranding an entire intent, also update its `subtle`, `subtleHover`,
`subtlePressed`, `subtleForeground`, `border` and `subtleBorder` tokens.
Check text contrast at 4.5:1 and relevant borders and focus indicators at 3:1
against their actual backgrounds, in both light and dark modes.

Variables inherit through the DOM. An explicit theme on a descendant can
redeclare color tokens and replace inherited overrides; target that theme
element too when it should keep the brand. Portals rendered outside the scoped
ancestor do not inherit its variables: use document-level overrides or a portal
container inside the scope when supported by the component.

## Light and dark overrides

The root follows the OS preference unless an explicit theme is set.
`data-theme="light"` and `data-theme="dark"` select a theme on the element that
carries the attribute. Match the same element when overriding its defaults:

<Source language="css" code={customizationExample5} />

If you select themes with `.choco-vanille-theme-light` or `.choco-vanille-theme-dark`, include
those classes alongside the corresponding attribute selectors above.
`ThemeProvider` manages `data-theme` in React; it does not change this CSS
override mechanism.

## Vanilla Extract recommendations

Use your application's configured Vanilla Extract bundler plugin and author
styles in `.css.ts` files. Import the public `vars` contract for autocompletion
and compile-time checks of token paths; it references the same CSS variables,
not a separate theme.

Use `globalStyle` for document or attribute-scoped overrides, or `style` for
a local class. Set existing tokens through the `vars` field rather than
creating a second theme contract or copying variable names:

<Source language="ts" code={customizationExample6} />

Read tokens directly in other styles, for example
`color: vars.color.surface.foreground` and `padding: vars.space[12]`.
These references follow the active scope automatically. The same cascade,
inheritance, dark-mode and contrast recommendations apply to Vanilla Extract
and plain CSS overrides.
